# AI Handover Guard V0.3 検証レポート

## 1. 検証目的

AIが申し送り文から抽出した結果を、そのまま採用せずPythonで再監査できるか確認しました。対象はすべて架空の申し送りです。

## 2. 検証条件

| 項目 | 内容 |
|---|---|
| 実施日 | 2026-09-16 |
| モデル | GPT-5.6 Luna |
| 件数 | 10件 |
| 入力 | `data/trial_10.csv` |
| 正解表 | `data/expected_labels.csv` |
| 出力方式 | Structured Outputs |
| 自動再試行 | なし |
| 1件当たり最大出力 | 300トークン |

## 3. 改善経過

| 版 | 主な変更 | 入力トークン | 出力トークン | 概算料金（USD） |
|---|---|---:|---:|---:|
| V0.1 | 初回の実API試験 | 3,896 | 549 | 0.001438 |
| V0.2 | 敬称除去、共有情報の空欄化、優先度説明 | 5,336 | 609 | 0.001798 |
| V0.3 | 異音・予備電源・定例更新の優先度基準を明確化 | 5,946 | 561 | 0.001862 |
| 合計 | 3回・30件処理 | 15,178 | 1,719 | 0.005098 |

V0.1では担当者名の「さん」が完全一致を妨げ、共有情報にも作業内容が出力されました。V0.2で両方を修正しましたが、設備異音・予備電源・定例更新の優先度に不一致が残りました。V0.3で基準を明確化し、AI優先度とPython優先度の両方が10件すべて正解しました。

## 5. 対応内容の表現差

正規化後も不一致となった3件を人が確認しました。

| ID | 正解表 | AI出力 | 確認結果 |
|---|---|---|---|
| H002 | 取引先へ請求金額を確認する | 取引先へ請求書の金額の違いを確認する | 同じ作業内容 |
| H005 | 照明を交換する | 会議室の照明を交換する | 対象場所を補った同じ作業内容 |
| H007 | 予備電源8の燃料補充を手配する | 予備電源8の燃料補充の手配 | 同じ作業内容 |

機械的な完全一致だけでは、正しい言い換えも不一致になります。本作品では完全一致、簡易正規化、人による意味確認を分け、評価を過大にも過小にもしない方針としました。

## 6. Python監査で確認できたこと

V0.2のAI試験では、優先度に次の3件の不一致がありました。

| ID | 内容 | AI | Python |
|---|---|---:|---:|
| H006 | 設備3号機の異音 | 中 | 高 |
| H007 | 予備電源の燃料不足 | 中 | 高 |
| H009 | 連絡網の定例更新 | 中 | 低 |

Pythonは3件すべてを `priority_audit_status=NEEDS_REVIEW` として検出しました。V0.3ではプロンプトも改善し、AIとPythonの両方が正解表と一致しました。

## 7. 判断

今回の10件では、担当者・期限・優先度・対応要否・監査判定がすべて正しく、対応内容も意味として10件すべて正しく抽出されました。AIとPythonを分離した第三者監査方式は、試作として狙いどおり動作しています。

ただし、10件の架空データだけでは一般性能や本番運用の安全性を証明できません。今後は件数、文体、業種、曖昧表現を増やし、誤警告率と不足検出再現率を測定する必要があります。
