# AI Handover Guard V0.3 検証レポート

## 1. 検証目的

AIが申し送り文から抽出した結果を、そのまま採用せずPythonで再監査できるか確認しました。対象はすべて架空の申し送りです。

## 2. 検証条件

| 項目 | 内容 |
|---|---|
| 実施日 | 2026-09-16 |
| モデル | GPT-5.6 Luna |
| 件数 | 10件 |
| 入力 | `data/trial_10.csv` |
| 正解表 | `data/expected_labels.csv` |
| 出力方式 | Structured Outputs |
| 自動再試行 | なし |
| 1件当たり最大出力 | 300トークン |

## 3. 改善経過

## 7. 判断

今回の10件では、担当者・期限・優先度・対応要否・監査判定がすべて正しく、対応内容も意味として10件すべて正しく抽出されました。AIとPythonを分離した第三者監査方式は、試作として狙いどおり動作しています。

ただし、10件の架空データだけでは一般性能や本番運用の安全性を証明できません。今後は件数、文体、業種、曖昧表現を増やし、誤警告率と不足検出再現率を測定する必要があります。

## 8. 追補：100件への拡大検証(2026-10-02)

7章の課題を受け、件数を10件から100件へ広げて、誤警告率と不足検出再現率を測定しました。

### 8.1 検証条件

| 項目 | 内容 |
|---|---|
| 実施日 | 2026-10-02 |
| モデル | GPT-5.6 Luna |
| 件数 | 100件 |
| 入力 | `data/raw_handover.csv` |
| 正解表 | `data/expected_labels.csv` |
| プロンプト | V0.3のまま変更なし |
| 実行回数 | 1回(結果を見てからの調整・やり直しなし) |
| 入力トークン | 59,496 |
| 出力トークン | 7,594 |
| 概算料金（USD） | 0.021012 |

本番の前に、APIキーの疎通確認として1件だけ実行しています(入力593・出力50トークン、概算0.000179ドル)。

### 8.2 データの構成

100件は100種類の文章ではなく、16種類の文型です。H001〜H006は1件ずつ、残りの10文型は番号や日付を変えて9〜10回ずつ繰り返します。2026-09-16の10件検証で試したのはH001〜H010の文型で、H011〜H016から始まる6文型は今回が初めてです。

### 8.3 結果

| 評価項目 | 100件 | うちH001〜H010 | うちH011〜H100 |
|---|---:|---:|---:|
| 対応内容・完全一致 | 59/100 | 7/10 | 52/90 |
| 対応内容・正規化一致 | 70/100 | 8/10 | 62/90 |
| 担当者 | 100/100 | 10/10 | 90/90 |
| 期限 | 91/100 | 10/10 | 81/90 |
| AI優先度 | 97/100 | 10/10 | 87/90 |
| Python優先度 | 100/100 | 10/10 | 90/90 |
| 対応要否 | 100/100 | 10/10 | 90/90 |
| 監査判定 | 91/100 | 10/10 | 81/90 |
| 全項目・完全一致 | 58/100 | - | - |
| 全項目・正規化一致 | 69/100 | - | - |

H001〜H010の対応内容は、同じ入力でも2026-09-16(完全一致4/10・正規化一致7/10)と今回(7/10・8/10)で結果が違いました。AIの表現は実行ごとに変わります。

### 8.4 監査判定の内訳(不足検出再現率・誤警告率)

| 正解 | 件数 | 正しく判定 | 誤って判定 |
|---|---:|---:|---:|
| NEEDS_REVIEW(要確認) | 49 | 40 | 9(READYと判定) |
| READY(問題なし) | 41 | 41 | 0 |
| INFO_ONLY(共有のみ) | 10 | 10 | 0 |

- 不足検出再現率：40/49(約82%)
- 誤警告率：0/51(0%)

見逃した9件は、すべて同じ文型「吉田さん、例の件を○月○日17時までにお願いします」です(H016、H026、…、H096)。正解は「作業内容が不明なので要確認」ですが、AIが作業内容に「例の件」(7件)または「例の件をお願いします」(2件)と出力しました。Python監査は作業内容が空欄かどうかだけを見るため、9件とも「問題なし」になりました。この文型は10件検証には含まれていませんでした。

### 8.5 期限の不一致(9件)

9件は、すべて同じ文型「発注番号○の数量に相違があります。○月○日までに仕入先へ確認してください」です(H011、H021、…、H091)。文中に時刻がありません。

| AIの出力 | 件数 | 正解表 |
|---|---:|---|
| 日付 23:59 | 5 | 日付 17:00 |
| 日付のみ(時刻なし) | 3 | 日付 17:00 |
| 日付 00:00 | 1 | 日付 17:00 |

正解表の17:00は文中にない前提であり、プロンプトも時刻がない場合の扱いを指示していません。AIの誤りというより、仕様が決まっていないことによる不一致です。ただし出力が3通りにばらつく点は課題です。

日付のみが出力された3件(H011、H021、H031)は、期限超過の判定が`YYYY-MM-DD HH:MM`形式しか読み取れないため、「期限が未確定のため判定できません」と表示され、判定の対象から外れました。これは監査側の不具合でした(2026-10-02に修正済み。日付のみの期限は、その日の終わりまで有効として判定します。`docs/SPEC.md` 14.3)。この章の数値は修正前の実行結果であり、変更していません。

### 8.6 AI優先度の不一致(3件)

|---|---|---:|---:|---:|
| H026 | 例の件を09月19日17時までに | 中 | 低 | 中 |
| H044 | 共用スペース5の照明が点滅 | 低 | 中 | 低 |

Pythonは3件すべてを `priority_audit_status=NEEDS_REVIEW` として検出しました。6章と同じく、AIとPythonを分ける設計が働いています。

### 8.7 対応内容の表現差

完全一致しなかった41件のうち、11件は語尾の「する」を省いただけで、正規化一致では正解になります。正規化後も不一致となった30件を、文型ごとに確認しました。

| 文型 | 件数 | 正解表 | AI出力の例 | 確認結果 |
|---|---:|---|---|---|
| 発注番号の数量相違 | 9 | 仕入先へ発注数量を確認する | 発注番号1011の数量について仕入先へ確認する | 発注番号を補った同じ作業内容 |
| 配送便の未着 | 9 | 配送便6について運送会社へ連絡する | 運送会社へ連絡する | 作業は同じだが、どの便かの番号が抜けている |
| 例の件 | 9 | (空欄) | 例の件 | 誤り(8.4の見逃し) |
| H002 | 1 | 取引先へ請求金額を確認する | 取引先へ請求書の金額の違いを確認する | 同じ作業内容 |
| H005 | 1 | 照明を交換する | 会議室の照明を交換する | 対象場所を補った同じ作業内容 |
| H087 | 1 | 予備電源8の燃料補充を手配する | 予備電源8の燃料補充の手配 | 同じ作業内容 |

意味として同じ作業内容だったのは82件(正規化一致70件と、上の表の12件)、対象の番号が抜けたものが9件、誤りが9件です。

### 8.8 判断

担当者・対応要否・Python優先度は100件すべて正しく、誤警告もありませんでした。AI優先度のずれ3件も、Pythonの独立判定で検出できました。

一方で、10件検証では全問正解だった監査判定と期限に、不一致が9件ずつ見つかりました。どちらも10件検証に含まれていなかった文型です。特に、作業内容が曖昧な文を「問題なし」と判定した9件は、本作品の目的(曖昧さの警告)に直接かかわる見逃しです。

今回の検証の時点では修正を行わず、既知の課題として記録しました(`docs/SPEC.md` 14章)。そのうち日付のみの期限の不具合(14.3)だけは、のちに修正しています。同じ100件に合わせてプロンプトやルールを調整すれば点数は上がりますが、それでは未知の文章への強さを示せないためです。修正する場合は、新しい文型を含む別の試験データで検証し直す必要があります。

また、今回の100件は16種類の文型を1回実行した結果であり、一般性能や本番運用の安全性を証明するものではありません。
