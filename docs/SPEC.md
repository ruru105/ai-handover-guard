# AI Handover Guard 仕様書 V0.3

## 1. 作品の位置づけ

- 大分類：AI Business Workflow Automation
- 作品名：AI Handover Guard
- 日本語名：AI引き継ぎ漏れ防止ツール
- 目的：申し送り文章から次の行動を抽出し、担当・期限・作業内容などの不足を警告する

## 2. 誰でも理解できる一文仕様

> 職場の申し送りを「誰が・何を・いつまでに」へ整理し、決まっていない項目を知らせるツール。

## 3. 利用者

| 利用者 | 必要な情報 |
|---|---|
| 一般職員 | 自分が担当する作業、期限、注意点 |
| 管理者 | 担当者不明、期限不明、期限超過、重要案件 |
| 改善担当者 | 漏れや曖昧さが多い連絡の傾向 |

## 4. V0.3の対象範囲

### 実装するもの

- AIへ渡す原文と、人間が決めた正解表の分離
- AI抽出後を想定したCSVの読み込み
- 必須項目の不足判定
- 警告理由の作成
- 監査結果CSVの出力
- 項目別正解率と全項目正解率の計算
- 単体テスト
- OpenAI APIを使った最大10件の安全な抽出試験
- 担当者名の敬称正規化
- 項目ごとの不一致明細
- 保存済みAI回答の監査・評価一括実行
- AI優先度とPython優先度の独立比較
- 優先度不一致の要確認表示
- 対応内容の完全一致と正規化一致の分離

### まだ実装しないもの

- メール、Slackなどへの自動通知
- GUI
- 実在する職場データの利用
- AIによる自動返信

## 5. 入力項目

| 項目 | 説明 | 必須 |
|---|---|---|
| record_id | 申し送りの識別番号 | 必須 |
| submitted_at | 登録日時 | 必須 |
| source_department | 発信部署 | 必須 |
| message_text | 元の申し送り文章 | 必須 |
| extracted_action | AIが抽出した作業 | 条件付き必須 |
| extracted_assignee | AIが抽出した担当者 | 条件付き必須 |
| extracted_deadline | AIが抽出した期限 | 条件付き必須 |
| extracted_priority | AIが判定した緊急度 | 必須 |
| action_required | 対応が必要か | 必須 |

## 6. 監査ルール

対応が必要な申し送りでは、次の3項目を必須とします。

1. 作業内容
2. 担当者
3. 期限

不足がある場合は `NEEDS_REVIEW`、不足がない場合は `READY` とします。対応不要の場合は `INFO_ONLY` とします。

優先度はAI結果を上書きせず、Pythonが原文から独立判定した `rule_priority` と並べます。不一致は `priority_audit_status=NEEDS_REVIEW` として人が確認できるようにします。

## 7. 視点をずらした部分

一般的なAI要約ツールは「文章を短くする」ことが中心です。本作品は、要約の上手さではなく「次の行動が実行可能な状態になっているか」を監査します。

## 8. 高値更新として示す部分

- AIと固定ルールを組み合わせる
- 正解ラベル付きデータで性能を測る
- 利用者別の表示を設計する
- 処理件数ではなく、不足項目の発見率を評価する
- 将来は通知まで含む一連の業務フローにする

## 9. 成功指標（将来版）

| 指標 | 意味 |
|---|---|
| 項目抽出正解率 | 担当・作業・期限を正しく取り出せた割合 |
| 不足検出再現率 | 本当に不足している案件を見逃さなかった割合 |
| 誤警告率 | 問題のない案件を誤って警告した割合 |
| 処理時間 | 人が確認する場合と比べた所要時間 |

## 10. 設計原則

- 処理単位ごとに見出しやコメントを付ける
- AIが不確かなときは、人による確認へ回す
- 業種固有ルールは設定で変更可能にする
- 元文章と判定理由を残し、後から確認可能にする
- 個人情報を含む実データは使用しない
